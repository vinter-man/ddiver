# ddiver

Мониторинг ключевых слов в Telegram для модераторов, которые **не** являются админами чатов.

Слушает Telethon-сессия под вашим аккаунтом — в тех чатах, где вы просто участник. Когда
сообщение совпадает с вашими правилами, отдельный бот (в эти чаты его добавлять не нужно)
присылает вам в личку:

```
📡 Чат модерации
👤 Иван · @ivan · 42
🔗 https://t.me/c/1234567890/77
🕒 2026-09-22 14:03:05 +03:00 (Europe/Kyiv) · 12 сек назад
🔑 казино (правило чата)

Заходи в **казино** прямо сейчас
[🚫 Игнорировать отправителя] [➖ Добавить исключение]
```

## Что умеет

- **Следит за чатами, где у вас нет прав.** Ни админки, ни бота в чате.
- **Правила на каждый чат.** `казино` (подстрока, без учёта регистра), `=казино` (целое слово),
  `re:каз[иі]но` (регулярное выражение). Исключения — тот же синтаксис, и они важнее ключей.
- **Несколько модераторов, один слушатель.** Владелец открывает конкретные чаты; у каждого
  модератора свои чаты, правила, игнор-лист, язык и часовой пояс.
- **Переживает рестарты.** Совпадение сначала записывается в outbox и только потом отправляется,
  а пропущенное за время простоя бот дочитывает сам (с пометкой «пропущено, пока бот был офлайн»).
- **Держит нагрузку.** 50+ чатов и 100k+ сообщений в день: ограниченные очереди, общий
  флуд-шлюз, дайджесты при всплесках, автоотключение катастрофических регулярок.

## Что нужно

- Python 3.12+ (или Docker)
- `api_id` / `api_hash` с [my.telegram.org](https://my.telegram.org) → API development tools
- Токен бота у [@BotFather](https://t.me/BotFather)
- Ваш Telegram user id ([@userinfobot](https://t.me/userinfobot); `ddiver login` тоже его печатает)

## Установка

```bash
git clone https://github.com/vinter-man/ddiver && cd ddiver
cp .env.example .env         # заполните API_ID, API_HASH, BOT_TOKEN, OWNER_ID
uv sync                      # или: pip install -e .
uv run ddiver login          # телефон, код, 2FA — сессия останется в ./data
uv run ddiver check-config   # проверит токен, права на файлы и что вы нажали Start у бота
uv run ddiver run
```

Затем откройте своего бота в Telegram и нажмите **Start**.

В BotFather выполните `/setjoingroups` → **Disable**: бот пишет только вам.

### Docker

```bash
cp .env.example .env
docker compose run --rm -it ddiver login   # пока сервис НЕ запущен
docker compose up -d
docker compose logs -f
```

В `./data` лежат файлы сессий и база SQLite. **Никогда не запускайте два процесса ddiver на
одной папке data** — Telegram аннулирует сессию, которую используют из двух мест. ddiver держит
lock-файл и откажется стартовать, но копия папки в другом месте всё равно всё сломает.

## Как пользоваться

`/start` спросит язык и часовой пояс, дальше — меню:

| Меню | Что делает |
|---|---|
| 📡 Чаты | выбрать чаты для наблюдения (модераторам видны только открытые владельцем) |
| 🔑 Правила | ключевые слова и исключения, на чат или на все ваши чаты |
| 🚫 Игнор | отправители, о которых не нужно сообщать |
| ⚙️ Настройки | язык, часовой пояс, порог дайджеста |
| 📊 Статус | состояние слушателя, аптайм, счётчики, длина очереди |
| 🗂 Общие чаты | *(владелец)* какие из ваших чатов видят модераторы |
| 👥 Пользователи | *(владелец)* допустить, отказать, отозвать доступ |

Команды: `/menu` `/test <текст>` `/status` `/help` `/cancel`.

`/test` прогоняет настоящий конвейер (сначала исключения, потом правила чата, потом глобальные)
и показывает по каждому чату, пришло бы уведомление или нет.

### Синтаксис правил

| Шаблон | Совпадает |
|---|---|
| `казино` | любое сообщение со строкой «казино», без учёта регистра — включая «казино-бонус» |
| `=казино` | только целое слово, «казиношный» не подойдёт; пунктуация — граница, поэтому `=c++` работает |
| `re:каз[иі]но` | регулярное выражение (без учёта регистра; отключить — `(?-i:…)`) |
| `#промо` | хештег — обычное ключевое слово, синтаксиса комментариев нет |

Текст перед сравнением нормализуется и очищается от невидимых символов, поэтому
`ка<zero-width space>зино` всё равно совпадёт с `казино`. Латинские двойники кириллицы
(`кaзино` с латинской «a») **не** нормализуются — для них нужна регулярка.

Слишком медленная регулярка пропускается, а после трёх таймаутов отключается автоматически —
вам придёт сообщение, какая именно.

## Эксплуатация

- `ddiver health` возвращает ненулевой код, если heartbeat устарел; Docker использует это как
  healthcheck.
- Если сессия умерла (отозвана, бан, использовалась из двух мест), ddiver **не** уходит в цикл
  рестартов: бот продолжает работать, а в `/status` и сообщением вы увидите, что нужен
  `ddiver login`.
- В логах — сводка раз в 60 секунд плюс строка на уведомление; флуд-ожидания Telethon видны
  на уровне INFO.
- Бэкапьте `data/ddiver.sqlite3` — это конфигурация. Бэкап `data/user.session` — это бэкап
  **вашего аккаунта**, относитесь соответственно.

## Безопасность

`data/user.session` даёт полный доступ к вашему аккаунту: чтение всех чатов и отправка сообщений
от вашего имени. ddiver держит `data/` в режиме `0700`, файлы сессий — `0600`, не пишет тексты
сообщений в лог выше DEBUG и ничего не отправляет от вашего имени: только читает чаты и пишет
вам через бота.

Любой допущенный модератор видит тексты сообщений из тех чатов, которые вы ему открыли, в своей
личке с ботом. Открывайте только то, что действительно хотите показать.

Работа пользовательского аккаунта через API — серая зона в правилах Telegram. ddiver только
читает и не делает массовых вступлений и рассылок, то есть находится на наименее рискованном
краю, но риск не нулевой — при желании используйте отдельный аккаунт.

## Разработка

```bash
uv sync
uv run pytest -q          # ~350 офлайн-тестов, подключение к Telegram не нужно
uv run ruff check . && uv run ruff format --check .
uv run mypy
```

Архитектура, инварианты и обоснования — в [DESIGN.md](DESIGN.md). Всё, кроме `ddiver/runtime.py`,
не вызывает Telethon и тестируется офлайн с фейковыми клиентами и виртуальными часами.
