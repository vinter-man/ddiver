# ddiver

Мониторинг ключевых слов в Telegram для модераторов, которые **не** являются админами чатов.

Слушает Telethon-сессия под вашим аккаунтом — в тех чатах, где вы просто участник. Когда
сообщение совпадает с вашими правилами, отдельный бот (в эти чаты его добавлять не нужно)
присылает вам в личку:

```
📡 Чат модерации
👤 Иван · @ivan · 42
🔗 https://t.me/c/1234567890/77
🕒 2026-09-22 14:03:05 +03:00 (Europe/Kyiv) · 12 сек назад
🔑 такси (правило чата)

Дёшево подвезу, **такси** недорого, пишите
[🚫 Игнорировать отправителя] [🗑 Убрать это правило]
```

## Что умеет

- **Следит за чатами, где у вас нет прав.** Ни админки, ни бота в чате.
- **Правила на каждый чат.** `такси` (подстрока, без учёта регистра), `=такси` (целое слово),
  `re:такс[иі]` (регулярное выражение). Исключения — тот же синтаксис, и они важнее ключей.
- **Несколько модераторов, один слушатель.** Владелец открывает конкретные чаты; у каждого
  модератора свои чаты, правила, игнор-лист, язык и часовой пояс.
- **Переживает рестарты.** Совпадение сначала записывается в outbox и только потом отправляется,
  а пропущенное за время простоя бот дочитывает сам (с пометкой «пропущено, пока бот был офлайн»).
- **Рассчитан на нагрузку.** Проектировался под 50+ чатов и 100k+ сообщений в день:
  ограниченные очереди, общий флуд-шлюз, дайджесты при всплесках, автоотключение
  катастрофических регулярок. Самый долгий замер пока — 1301 сообщение за пять часов.

## Что нужно

- Python 3.12+ (или Docker)
- `api_id` / `api_hash` с [my.telegram.org](https://my.telegram.org) → API development tools
- Токен бота у [@BotFather](https://t.me/BotFather)
- Ваш Telegram user id ([@userinfobot](https://t.me/userinfobot); `ddiver login` тоже его печатает)

## Установка

```bash
git clone https://github.com/vinter-man/ddiver && cd ddiver
cp .env.example .env         # заполните API_ID, API_HASH, BOT_TOKEN, OWNER_ID
uv sync                      # или: pip install -e .
uv run ddiver login          # телефон, код, 2FA — сессия останется в ./data
uv run ddiver check-config   # проверит токен, права на файлы и что вы нажали Start у бота
uv run ddiver run
```

Затем откройте своего бота в Telegram и нажмите **Start**.

В BotFather выполните `/setjoingroups` → **Disable**: бот пишет только вам.

### Docker

```bash
cp .env.example .env
docker compose run --rm -it ddiver login   # пока сервис НЕ запущен
docker compose up -d
docker compose logs -f
```

В `./data` лежат файлы сессий и база SQLite. **Никогда не запускайте два процесса ddiver на
одной папке data** — Telegram аннулирует сессию, которую используют из двух мест. ddiver держит
lock-файл и откажется стартовать, но копия папки в другом месте всё равно всё сломает.

Про VPS — скрипт первичной настройки, деплой по пушу и как ужиться с другими проектами на той
же машине — см. [deploy/README.md](deploy/README.md).

## Как пользоваться

`/start` спросит язык и часовой пояс, дальше — меню:

| Меню | Что делает |
|---|---|
| 📡 Чаты | выбрать чаты для наблюдения (модераторам видны только открытые владельцем) |
| 🔑 Правила | ключевые слова и исключения, на чат или на все ваши чаты |
| 🚫 Игнор | отправители, о которых не нужно сообщать |
| ⚙️ Настройки | язык, часовой пояс, порог дайджеста, учитывать ли сообщения ботов |
| 📊 Статус | состояние слушателя, аптайм, счётчики, длина очереди |
| 🗂 Общие чаты | *(владелец)* какие из ваших чатов видят модераторы |
| 👥 Пользователи | *(владелец)* допустить, отказать, отозвать доступ |

Команды: `/menu` `/test <текст>` `/status` `/export` `/import` `/help` `/cancel`.

`/test` прогоняет настоящий конвейер (сначала исключения, потом правила чата, потом глобальные)
и показывает по каждому чату, пришло бы уведомление или нет.

### Синтаксис правил

| Шаблон | Совпадает |
|---|---|
| `такси` | любое сообщение со строкой «такси», без учёта регистра — включая «мототакси» |
| `=такси` | только целое слово, «таксист» не подойдёт; пунктуация — граница, поэтому `=c++` и «такси-сервис» работают |
| `re:такс[иі]` | регулярное выражение (без учёта регистра; отключить — `(?-i:…)`) |
| `#промо` | хештег — обычное ключевое слово, синтаксиса комментариев нет |

Текст перед сравнением нормализуется и очищается от невидимых символов, поэтому
`та<zero-width space>кси` всё равно совпадёт с `такси`. Латинские двойники кириллицы
(`тaкси` с латинской «a») **не** нормализуются — для них нужна регулярка.

Слишком медленная регулярка пропускается, а после трёх таймаутов отключается автоматически —
вам придёт сообщение, какая именно.

## Эксплуатация

- `ddiver health` возвращает ненулевой код, если heartbeat устарел; Docker использует это как
  healthcheck.
- Если сессия умерла (отозвана, бан, использовалась из двух мест), ddiver **не** уходит в цикл
  рестартов: бот продолжает работать, а в `/status` и сообщением вы увидите, что нужен
  `ddiver login`.
- В логах — сводка раз в 60 секунд плюс строка на уведомление; флуд-ожидания Telethon видны
  на уровне INFO.
- `/export` отдаёт JSON с вашими чатами, правилами и игнор-листом; `/import` загружает его
  обратно, **добавляя**, а не заменяя. Это и есть бэкап, который стоит держать вне машины:
  сессии и токена там нет, так что его можно класть туда, куда обычно кладут бэкапы.
- Копия `data/user.session` — это копия **вашего аккаунта Telegram**. Если бэкапите каталог
  целиком, кладите его туда, куда не побоялись бы положить пароль.

## Наблюдение

Ничего из этого не обязательно — ddiver работает и без него.

### Мёртвая рука

Задайте `PING_URL`, и ddiver будет дёргать его раз в минуту (`PING_INTERVAL`). Направьте на push-монитор
— бесплатный healthchecks.io, push-URL в Uptime Kuma, что угодно, что поднимает тревогу, когда
пинги прекратились:

```dotenv
PING_URL=https://hc-ping.com/ваш-uuid
```

Это единственный сигнал, который переживёт смерть самой машины, — а именно так и выглядит
«тишина в чате». Всё остальное ниже крутится на той же машине и о собственных похоронах
сообщить не может.

### Метрики, логи и дашборды

```bash
docker compose -f docker-compose.yml -f deploy/docker-compose.observability.yml up -d
ssh -L 3000:127.0.0.1:3000 you@your-box   # Grafana слушает только localhost
```

Grafana окажется на <http://127.0.0.1:3000> (admin/admin, если не задали `GRAFANA_USER` и
`GRAFANA_PASSWORD`), с уже готовым дашбордом: жив ли, сообщений и совпадений в секунду,
доставка и флуд-ожидания, таймауты правил, CPU и память хоста, плюс панель с поиском по логам.
Замеры на свежем стеке: Prometheus 57 МБ, Loki 72 МБ, Grafana 99 МБ, Alloy 48 МБ — около
280 МБ против 56 МБ у самого ddiver, и дальше растёт вместе с глубиной хранения. Закладывайте
полгигабайта, и сюрпризов не будет; то, что обвязке нужно в несколько раз больше, чем боту, —
причина держать её в отдельном compose-файле.

Метрики хоста включаются флагом `--profile host-metrics`: node-exporter требует настоящий `/`
хоста, а Docker Desktop такое монтирование запрещает. На Linux-машине включите профиль, и
панель «Host» заполнится; до тех пор она пустая, а цель `node` в Prometheus висит down.

Алертам в Telegram нужны две переменные в `.env`. `deploy/render-alerts.sh` пишет из них
файлы провижининга при каждом деплое и убирает их на машине, где алертов нет: Grafana не
стартует, если у контакта нет токена, так что их надо именно отсутствие, а не пустота.

Без Docker: `METRICS_PORT=9109` поднимает `/metrics` сам по себе, а `LOG_FORMAT=json` делает
логи машиночитаемыми.

Grafana умеет писать вам в Telegram, когда что-то сломалось, но машина ещё жива: сессии нужен
повторный вход, слушатель отключён десять минут, уведомления копятся. Подойдёт тот же бот —
это один токен вместо двух, и так проще всего. **Второй** бот лучше, если хочется надёжнее:
сообщение о вставшей доставке тогда не едет через бота, который и встал, а отзыв одного токена
не выключает сразу оба канала.

```dotenv
ALERT_TELEGRAM_TOKEN=123456:AA...
ALERT_TELEGRAM_CHAT_ID=ваш-числовой-id
```

Отдельный compose-файл не нужен: задаёте две переменные, и следующий деплой их подхватит.
Вручную:

```bash
./deploy/render-alerts.sh && docker compose -f docker-compose.yml \
    -f deploy/docker-compose.observability.yml up -d grafana
```

### Как спросить агента про логи

Логи приезжают в Loki как JSON, с `level` и `logger` в метках — то есть по ним можно делать
запросы, а не grep: `{service="ddiver", level="ERROR"} | json | msg =~ ".*flood.*"`. Подключите
LLM-агента к MCP-серверу Grafana (`grafana/mcp-grafana`), и «сходи разберись, почему утром из
того чата ничего не пришло» станет вопросом, на который он ответит сам.

## Приватность

ddiver читает чаты, в которых вы состоите, а люди в них ни на что не соглашались. Это стоит
понимать до запуска — и до того, как вы откроете чаты другим модераторам:

- **Что хранится.** Только совпавшие сообщения, никогда не весь поток. На каждое совпадение:
  текст, название чата, id отправителя, его имя и @username, ссылка. Несовпавшие сообщения
  проверяются в памяти и забываются.
- **Как долго.** Семь дней, потом ежедневная задача их удаляет. Остальное в базе —
  конфигурация: ваши чаты, правила и игнор-лист.
- **Кто может прочитать.** Все, у кого есть доступ к диску машины, плюс каждый модератор,
  которому вы открыли чат: текст сообщений этого чата придёт ему в личку.
- **Что уходит наружу.** Уведомления в личку модераторам через вашего бота — и больше ничего.
  Ни телеметрии, ни сторонних сервисов.
- **Как удалить.** Удаление правила останавливает новые совпадения; старые лежат в
  `data/ddiver.sqlite3`, пока не истекут семь дней или пока вы не удалите файл.

Если вы в ЕС, это персональные данные по GDPR, и запуская бота вы становитесь контролёром. Для
личного инструмента модерации планка невысокая, но это не «ничего».

## Безопасность

`data/user.session` даёт полный доступ к вашему аккаунту: чтение всех чатов и отправка сообщений
от вашего имени. ddiver держит `data/` в режиме `0700`, файлы сессий — `0600`, не пишет тексты
сообщений в лог выше DEBUG и ничего не отправляет от вашего имени: только читает чаты и пишет
вам через бота.

Любой допущенный модератор видит тексты сообщений из тех чатов, которые вы ему открыли, в своей
личке с ботом. Открывайте только то, что действительно хотите показать.

Работа пользовательского аккаунта через API — серая зона в правилах Telegram. ddiver только
читает и не делает массовых вступлений и рассылок, то есть находится на наименее рискованном
краю, но риск не нулевой — при желании используйте отдельный аккаунт.

## Разработка

```bash
uv sync
uv run pytest -q          # ~470 офлайн-тестов, подключение к Telegram не нужно
uv run ruff check . && uv run ruff format --check .
uv run mypy
```

Архитектура, инварианты и обоснования — в [DESIGN.md](DESIGN.md). Обращения к Telegram
сосредоточены в `runtime.py`, `clients.py`, `login.py`, CLI и адаптере `telethon_history`
в конце `catchup.py`. Всё остальное получает свою часть Telegram как внедрённый порт —
`BotPort`, `History`, `EntityResolver`, — поэтому сопоставление, хранение, доставка и
форматирование проверяются офлайн на фейках и виртуальных часах.
